14 August 2026

New: branches and release builds beside mainline, compare any two, a long-running branch gets its own dashboard, plus the Watch page

Fixed: a scoped page could leak other products' environments

  • On a site with more than one product, scoping the home screen to one product (or opening a branch/build's own dashboard) could still offer every OTHER product's environments in the picker and the "last reported" pills, even though every number on the page was already correctly scoped. Found in live testing; fixed — both now only ever list the environments that actually belong to the page you're looking at.
  • The Build/branch picker box and the comparison page's "Compare to" box looked out of place next to every other control on the toolbar — a styling gap left over from switching them to a type-to-filter field. Fixed; they now match.
  • Jumping from a Watch card into the dashboard could land on a blank page. Opening a card for a product different from whatever this browser's Product switcher last had selected set the environment filter correctly but left the switcher on the OLD product — so the page rendered scoped to the wrong one, and the environment filter matched nothing under it. Fixed: every card's link now names its own product, and the page adopts it — the switcher updates to match, and that becomes your new default from then on, exactly as if you'd picked it yourself.
  • The Time and Timeline pages can now actually show a branch's own data — the pages could already be asked for it on the wire, but neither one knew how to read that request from its own URL, so there was no way to get there. Both now carry the same "you are scoped to a branch" band the dashboard already shows, and expanding a row on a branch's Timeline (or using its test-search box) now correctly reads that branch's own runs, not mainline's.
  • A few more links that quietly lost track of which branch you were looking at, fixed. An Open Actions row assigned from a branch now opens that SAME branch's test page, not mainline's. "View in timeline" and "Open full test page" from a branch's own triage panel now open that branch's own pages too. And a branch's "Its own results" tab now has two direct links — "This branch's Time" / "This branch's Timeline" — into its own numbers.

New: branches and builds, compared to mainline

  • A CI branch or a one-off build can now show up beside your nightly results, without touching them — mainline stays exactly what it always was, and nothing about this is visible until your team actually feeds in a branch or a build. Once one exists, a Build picker appears next to the Environment filter on the dashboard, listing branches then builds (newest build first) — type any part of a name to filter the list; pick one to see it compared against mainline.
  • The comparison page shows what's new: failing, passing, still failing on both, brand-new tests, and tests with no result on one side — each a tab with its own table, plus how many tests agree and are not worth listing, and how much of the estate has a result on this branch at all. Both sides' "last ran" times are shown, and a warning appears if the comparison's other side hasn't run recently enough to trust it.
  • Triage works from a branch too — every row in the comparison table can be assigned (or taken) right there, and "Review" opens the same output/comment panel you already know from the home screen and Open actions. A branch failure never offers to retire the test — that stays a mainline call — but otherwise it is the same triage you already do, one click closer. A sticky band across the top of the page (and the test's own page, if you follow a row there) always says which branch or build you're looking at, and what it's being compared against, so it's never a mystery how you got there.
  • Open a test from a branch's or build's table and its page now shows the comparison result right beside its own, and any comment on that test says which build or branch it was posted from.
  • That test page's link to its suite's own execution history still opens mainline's (script history isn't scoped to a branch or build yet) — it now says so, both on hover and right next to the link, instead of quietly landing somewhere you didn't expect.
  • Open actions shows where an assignment came from. If a test was assigned while looking at a branch or build, its row carries a small tag saying which one — and once at least one assignment has come from a branch, a filter appears alongside the owner filters to show only branch-originated items, or only mainline's own.
  • The Watchlist (below) can carry a branch/build card too — add one from the "Branch/build" option in the card picker to keep an eye on a branch's or build's health alongside your usual environments and products.
  • If your site's feeder script submits branch or build results, see the README's "Feeding a branch or build" section for the new --branch/--build flags.

New: release builds — compare against any earlier build, not just mainline

  • A build can now be judged against the build before it, not only against mainline. Open a build's comparison page and a new Compare to box appears above the numbers — it defaults to the build's own predecessor when one exists (the last time this same build name was cut, this box shows which one it picked), and falls back to mainline when there isn't one yet. Type or pick any other build or branch of the same product to compare against that instead — nothing is parsed out of the version string; builds are always ordered by when they actually ran, never by name.
  • A build's page now says when it was built and whether anything has run since — "Built 2 days ago — nothing has run since" if it hasn't been re-cut, or its last run time if it has.
  • A build's page now names both baselines at once. Right under the header, a line reads "vs build 1.0.0: 4 new failures · 2 fixed — vs mainline: 6 new failures" — whichever baseline you're currently looking at plus the other one, so you don't have to switch the Compare to box back and forth to ask "but is it good against mainline too?" It fills in a moment after the rest of the page (a second lookup), and stays hidden entirely for the very first build of a product, which has no earlier build to name.
  • A test's own page can now show its result on every build and branch of its product at once. Open the new "Every build" section below Analytics: one row per stream that has ever run this test, newest first, with the ones that never ran it plainly marked no result rather than left off the table or guessed at. There's also a quick switcher near the top of the page — pick any stream from the list and jump straight to this same test's result there.
  • A Watchlist card for a build now says how many tests are failing in it by name, and compares it against its predecessor build when one exists — the same default the comparison page uses — falling back to mainline otherwise.
  • Comparing two builds (or a build and a branch) from different products is refused with a clear message naming both — there is nothing to compare across products, since they don't share environments.

New: a long-running branch gets its own dashboard

  • A branch that runs nightly for weeks now reads like a second small testboard, not just a diff against mainline. Open a branch with enough history and you'll see two tabs at the top: Its own results (the same tiles, trend chart and triage queues you already know from the home screen — scoped to that branch alone) and Difference from mainline (the comparison view from the August drop above, unchanged). Both tabs are always there for a branch; which one opens first depends on how much history the branch has, and a line under the tabs says exactly why in plain words — "this branch has completed 8 passes in the last 14 days" or similar, never a silent guess.
  • The Time and Timeline pages can now be scoped to a branch too (via the same picker, from a branch's own dashboard) — so "where did the suite's time go last night" and "what order did scripts run in" both work for a branch's own nightly run, not only for mainline.
  • The comparison view now says, in one line, how much of what's failing on a branch is really new there versus already broken on mainline too — "Of 4 tests failing here, 1 also fails on mainline too" — so a branch's own regressions don't get lost in mainline's existing noise.
  • Mainline is completely unaffected either way — a branch's own nightly history has never counted toward mainline's trend, staleness, or triage queues, and this drop keeps it that way.

New page: Watch

  • One page, the sets you actually check. Add a card for any environment (and, once a second product exists, any product) you're responsible for; each card shows what's failing, what's new, what's been fixed, and when it was last heard from — dated in its own words, not one page-wide timestamp. Click a card to open that scope on the dashboard.
  • The URL is the whole page. There's no login and nothing saved on the server — build the page once, click Copy link, and send the URL to whoever else needs it. Use Save as my default so a bare visit to the Watch page always opens to yours.
  • Reorder and remove with the arrows on each card — no drag-and-drop to fight with. A card for a name that no longer exists says so plainly rather than just vanishing, so an old shared link never looks like it silently lost something.
  • Find it in the nav on every page, labelled Watch.
  • A card with a failing, unowned test now says so at a glance. Any environment, product or branch/build card with at least one currently-failing test that nobody has taken gets a red-tinted border and an "Unassigned failing" count right on the card — colour is never the only signal, the number is always there in words too. A card with nothing unassigned looks exactly as it always has.
  • That count is now a way in, not just a number. Click it on an environment or product card and the dashboard opens already filtered to exactly those failing, unassigned tests. On a branch/build card it opens that branch's own scoped dashboard instead, where every failing row already shows its assignee inline. The dashboard itself also gained a plain Unassigned only chip next to the result filters, for starting that same filter from scratch.
  • Cards can now declare how often they're expected to report. Add @1d, @7d, or a custom hour count to a card from the new dropdown next to the picker (or by hand in the URL, e.g. c=e:win-sim@36h) and the card gets an amber border plus a line saying so — "expected within 1d — last run 3 days ago" — when it's overdue. A card with no declared cadence behaves exactly as before; this is entirely optional per card.

Under the hood: products

  • testboard can now group environments into products, for sites that run more than one. Nothing changes for anyone on a single-product install — no new switcher, no new column, nothing to configure. Once a second product is declared (in the "Environment expectations" section of Open actions, which now has a Product cell alongside the existing one), a Product picker appears at the top of every page, and the home screen and Open actions' tables gain a Product column so mixed views stay readable — scoped to one product, the column disappears again and the page says so.
  • Declaring products for an estate that already has a lot of environments got faster. The same "Environment expectations" section now offers an "Assign N unmapped environments" button whenever at least one environment has no product yet — type the product name once and it's applied to every currently-unmapped environment in one action, instead of one at a time. It disappears once nothing is left unmapped.

7 August 2026

New: the Timeline — what ran, in what order

Fixed: a rare failed action on a busy dashboard

  • Very occasionally, posting a comment or assigning a test on a busy dashboard failed for no visible reason and worked on the second try. That was a server bug in how idle connections were recycled — found by its own test — and it is fixed.

New page: Timeline

  • One environment's scripts, in running order — built for the poisoned-data hunt. When a test fails because an earlier script left data in a bad state, the culprit is somewhere above it in this list. Rows open to their tests, tests open to their output, so the whole read happens in one place — and the run picker replays any recorded run: "Earlier runs…" reaches back through everything on file, not just the recent fortnight.
  • Start from the victim. "Find test" jumps to a test's place in the order — or use View in timeline, which now appears wherever a run's output does (the triage panels, and each History row on a test's page — old rows land in that night's run, not the latest).
  • Keys, if you want them (the mouse does everything): press ? on the page for the list — / to search, n/p through failures, Ctrl-j/Ctrl-k to cycle search suggestions, vim-style.

Under the hood

  • The dashboard can now run its database on a central server instead of a file. Nothing changes on any page — this is groundwork, and you will hear separately before anything moves.

31 July 2026

The home page got fast — and honest about loading

The dashboard loads much faster, and in stages

  • The numbers come up first. The tiles, the charts and the counts on every triage tab paint as soon as they are ready, instead of the whole page waiting for its slowest part. The rows of the queue you are looking at follow a moment later; while they are on their way the table says "Loading queue…" rather than showing you nothing.
  • The other triage tabs load when you open them. The counts on the tab buttons are always live, but a tab's rows are fetched the first time you click it — so the page no longer downloads five tables you may never look at. Switching back to a tab you have already opened is instant.
  • The Time page and the stale-test filter got the same speed-up under the hood — the calculation that decides "recently run" is hundreds of times cheaper than it was.

Retiring a test now sticks

  • Retirements were being silently undone within minutes. The system that pushes results re-sends recent runs on a schedule, and the dashboard mistook every re-send for the test "running again" — so it quietly un-retired it and left a comment saying so. If you retired a test and found it back in your queues with an "Automatically un-retired" comment, that was this. A test now comes back only when it genuinely reports something new.

30 July 2026

Fixes, and a new look for the Time page

All of this is live now. Hard-refresh if a page looks the same as it did yesterday.

The Time page works again

  • It was failing to load entirely for anyone whose estate had a test that had stopped reporting — which in practice meant everyone, every day. It is fixed, and the page now says how many tests it left out and since when.
  • Where the time goes is now a box graph, the kind you get from a profiler. The whole rectangle is the run time above it; each box is one environment, sized by its share. Click a box for the scripts inside it, and a script for its tests, with the trail back along the top. A box's size is its share of the time — so a script taking 1% of the night takes 1% of the picture, and the boxes too small to label say so rather than pretending.
  • Hovering a box shows its total, its share, and its mean per test. The sortable table underneath still lists every row, including the ones too small to draw a name in.

Dashboard

  • The "Last update" pills are now buttons. Click the environment you were checking the clock for and the whole page scopes to it; click it again to go back to everything. Every environment stays listed either way, with the selected one filled in.

Pages that would not load

  • Fixed the stall where a page hung until you gave up. Browsers hold connections open after they have finished with them, and the server was letting them keep a worker each — so a couple of tabs left open on someone's desk could stop everyone else's pages loading, with the server completely idle. It now takes those connections back. Measured on the reproduction: a request that waited 5 seconds behind idle browsers now waits 0.24.

This page

  • The "What's new" link now carries the date of the latest drop, with a dot beside it until you have read that one. It stops a change landing silently and being reported as a bug a week later.
  • Local changes appear here too. Anything fixed outside testboard on the same day — a reader, a rebuilt box, a renamed environment — can be logged against the date and shows up under it, marked as coming from this site rather than from the build. Ask whoever runs the server to add one.

Anything looks wrong, say so today rather than working around it.

28 July 2026

First upgrade since launch

All of this is live now. Hard-refresh if a page looks the same as it did yesterday.

Open actions — most of the change is here

  • Triage without leaving the list. Open a row to read the output, add a comment, assign it, or retire it. The list keeps its place and the row updates where it sits, so working down a queue no longer means losing it.
  • Every failing row says when it last passed — and whether it broke or is just unreliable: "failed every one of the last 20 runs" versus "flaky — flips about 1 run in 3". Those need opposite responses and used to look identical. The open panel shows the last 20 runs as a strip.
  • Columns sort. Sorting covers the whole queue, not just the rows on screen, so it returns you to the first page.

Dashboard

  • The tiles no longer claim to be about "last night". They count each test's latest run since a cutoff derived from when the suite was last round, which after a quiet weekend is days wide — so the heading is now Latest results and the line beneath it names the actual cutoff. The "Not run" and Time-page captions said a fixed "36 hours" for the same reason and now say the real date.
  • Each environment says when it last reported, above the tiles. They run one after another and hours apart, so a single "last updated" for the estate is only the newest of them — it reads healthy while the environment you are waiting on has not started. Hover for the exact UTC time.
  • New failures and Fixed now read PASS → FAIL in one column: the current result solid, the superseded one ghosted. Previously the previous result was the loudest thing in the row, so a page of new failures read as a page of passes.
  • "Not run recently" now follows the suite's own rhythm instead of a fixed 36 hours. Monday mornings, and the environments that run first, no longer flag the whole estate as missing. Retirement offers use the same rule, so they stop appearing on healthy tests.
  • Sorting "All tests" is fast again — roughly 3 ms a page, down from ~200 ms.

Time — new tab

Where the suite's runtime actually goes: environments, then the scripts in one, then the tests in one script. Bars plus the numbers, sortable.

Users

A user can be deactivated, which takes a duplicate or departed account out of the assignee pickers. History and existing assignments are untouched, and it is reversible. Bottom of Open actions, under "Manage people".

Everywhere

The table pages use the width of the screen now, so long test names stop forcing a scrollbar inside the table on a wide monitor.

Anything looks wrong, say so today rather than working around it.
