14 August 2026

New: products, the Watch page, and uploaded builds compared against mainline or each other

What's new

  • Products. If your site runs more than one product, a Product switcher now appears at the top of every page, scoping everything on it to the one you pick — declared in the "Environment expectations" section of Open actions. Nothing changes if your site only runs one.
  • A new Watch page. Build a grid of cards for the environments, products and builds you personally check, and share the page by copying its URL — there's no login and nothing saved on the server. Find it in the nav, labelled Watch.
  • Uploading builds and comparing them. A CI build or a one-off upload can now show up beside your nightly results without touching them. Once one exists, a Build picker appears next to the Environment filter on the dashboard (and now on Time and Timeline too) — pick one to compare it against mainline, or use the Compare to box on its page to compare it against any other build of the same product instead.
  • Assigning from a build's failures. Every row in a build's comparison table can be assigned, taken, or reviewed right there — the same triage you already do on the home screen, one click closer. A build's failure never offers to retire the test; that stays a mainline call.
  • Per-build test history and suite pages. A test's own page now has an "Every build" section showing its result on every build of its product at once; a suite's execution history page now works for any build too, not only mainline.
  • Highlights and staleness cadences. Every Watch card leads with the two numbers a morning scan needs: unassigned failures (red and clickable when there are any) and how long ago the last result arrived. A card with a failing, unowned test also gets a red-tinted border; add @1d, @7d, or a custom hour count to a card to have it flag itself when it's overdue.
  • A long-running build gets its own dashboard. Open one that's been running for weeks and you'll see two tabs: Its own results (the same tiles, trend and triage queues as the home screen, scoped to it alone) and Difference from mainline — which one opens first, and why, is stated in a line under the tabs.
  • The test page's "Latest run" line now has its own "View in timeline" link — the same jump the dashboard's review panel already offered, so you no longer lose it by opening the full test page first.
  • Open actions now shows every assigned test, whatever its result. "Needs action" means failing, stale annotation, or assigned to someone — before, an assignment on a passing test (say, someone asked to investigate why a test didn't run on a build) simply appeared nowhere.
  • Assign or unassign everything you're looking at, in one click. Open actions now has a bulk control: assign every test matching your current filters to one person (with an optional note posted on each of them), or clear the lot — handy for cleaning up after an abandoned build, where dozens of assignments used to need clearing one row at a time.

7 August 2026

New: the Timeline — what ran, in what order

Fixed: a rare failed action on a busy dashboard

  • Very occasionally, posting a comment or assigning a test on a busy dashboard failed for no visible reason and worked on the second try. That was a server bug in how idle connections were recycled — found by its own test — and it is fixed.

New page: Timeline

  • One environment's scripts, in running order — built for the poisoned-data hunt. When a test fails because an earlier script left data in a bad state, the culprit is somewhere above it in this list. Rows open to their tests, tests open to their output, so the whole read happens in one place — and the run picker replays any recorded run: "Earlier runs…" reaches back through everything on file, not just the recent fortnight.
  • Start from the victim. "Find test" jumps to a test's place in the order — or use View in timeline, which now appears wherever a run's output does (the triage panels, and each History row on a test's page — old rows land in that night's run, not the latest).
  • Keys, if you want them (the mouse does everything): press ? on the page for the list — / to search, n/p through failures, Ctrl-j/Ctrl-k to cycle search suggestions, vim-style.

Under the hood

  • The dashboard can now run its database on a central server instead of a file. Nothing changes on any page — this is groundwork, and you will hear separately before anything moves.

31 July 2026

The home page got fast — and honest about loading

The dashboard loads much faster, and in stages

  • The numbers come up first. The tiles, the charts and the counts on every triage tab paint as soon as they are ready, instead of the whole page waiting for its slowest part. The rows of the queue you are looking at follow a moment later; while they are on their way the table says "Loading queue…" rather than showing you nothing.
  • The other triage tabs load when you open them. The counts on the tab buttons are always live, but a tab's rows are fetched the first time you click it — so the page no longer downloads five tables you may never look at. Switching back to a tab you have already opened is instant.
  • The Time page and the stale-test filter got the same speed-up under the hood — the calculation that decides "recently run" is hundreds of times cheaper than it was.

Retiring a test now sticks

  • Retirements were being silently undone within minutes. The system that pushes results re-sends recent runs on a schedule, and the dashboard mistook every re-send for the test "running again" — so it quietly un-retired it and left a comment saying so. If you retired a test and found it back in your queues with an "Automatically un-retired" comment, that was this. A test now comes back only when it genuinely reports something new.

30 July 2026

Fixes, and a new look for the Time page

All of this is live now. Hard-refresh if a page looks the same as it did yesterday.

The Time page works again

  • It was failing to load entirely for anyone whose estate had a test that had stopped reporting — which in practice meant everyone, every day. It is fixed, and the page now says how many tests it left out and since when.
  • Where the time goes is now a box graph, the kind you get from a profiler. The whole rectangle is the run time above it; each box is one environment, sized by its share. Click a box for the scripts inside it, and a script for its tests, with the trail back along the top. A box's size is its share of the time — so a script taking 1% of the night takes 1% of the picture, and the boxes too small to label say so rather than pretending.
  • Hovering a box shows its total, its share, and its mean per test. The sortable table underneath still lists every row, including the ones too small to draw a name in.

Dashboard

  • The "Last update" pills are now buttons. Click the environment you were checking the clock for and the whole page scopes to it; click it again to go back to everything. Every environment stays listed either way, with the selected one filled in.

Pages that would not load

  • Fixed the stall where a page hung until you gave up. Browsers hold connections open after they have finished with them, and the server was letting them keep a worker each — so a couple of tabs left open on someone's desk could stop everyone else's pages loading, with the server completely idle. It now takes those connections back. Measured on the reproduction: a request that waited 5 seconds behind idle browsers now waits 0.24.

This page

  • The "What's new" link now carries the date of the latest drop, with a dot beside it until you have read that one. It stops a change landing silently and being reported as a bug a week later.
  • Local changes appear here too. Anything fixed outside testboard on the same day — a reader, a rebuilt box, a renamed environment — can be logged against the date and shows up under it, marked as coming from this site rather than from the build. Ask whoever runs the server to add one.

Anything looks wrong, say so today rather than working around it.

28 July 2026

First upgrade since launch

All of this is live now. Hard-refresh if a page looks the same as it did yesterday.

Open actions — most of the change is here

  • Triage without leaving the list. Open a row to read the output, add a comment, assign it, or retire it. The list keeps its place and the row updates where it sits, so working down a queue no longer means losing it.
  • Every failing row says when it last passed — and whether it broke or is just unreliable: "failed every one of the last 20 runs" versus "flaky — flips about 1 run in 3". Those need opposite responses and used to look identical. The open panel shows the last 20 runs as a strip.
  • Columns sort. Sorting covers the whole queue, not just the rows on screen, so it returns you to the first page.

Dashboard

  • The tiles no longer claim to be about "last night". They count each test's latest run since a cutoff derived from when the suite was last round, which after a quiet weekend is days wide — so the heading is now Latest results and the line beneath it names the actual cutoff. The "Not run" and Time-page captions said a fixed "36 hours" for the same reason and now say the real date.
  • Each environment says when it last reported, above the tiles. They run one after another and hours apart, so a single "last updated" for the estate is only the newest of them — it reads healthy while the environment you are waiting on has not started. Hover for the exact UTC time.
  • New failures and Fixed now read PASS → FAIL in one column: the current result solid, the superseded one ghosted. Previously the previous result was the loudest thing in the row, so a page of new failures read as a page of passes.
  • "Not run recently" now follows the suite's own rhythm instead of a fixed 36 hours. Monday mornings, and the environments that run first, no longer flag the whole estate as missing. Retirement offers use the same rule, so they stop appearing on healthy tests.
  • Sorting "All tests" is fast again — roughly 3 ms a page, down from ~200 ms.

Time — new tab

Where the suite's runtime actually goes: environments, then the scripts in one, then the tests in one script. Bars plus the numbers, sortable.

Users

A user can be deactivated, which takes a duplicate or departed account out of the assignee pickers. History and existing assignments are untouched, and it is reversible. Bottom of Open actions, under "Manage people".

Everywhere

The table pages use the width of the screen now, so long test names stop forcing a scrollbar inside the table on a wide monitor.

Anything looks wrong, say so today rather than working around it.
