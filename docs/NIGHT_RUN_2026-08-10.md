## 5. Phase 3 — the URL prefix (nginx)

**Requirement:** the server optionally accepts `testboard/` in front
of all paths, so nginx can proxy `/testboard/` to it.

**Design (decided with the user, 2026-08-10 — §0):**

1. **A server flag `--url-prefix`, DEFAULT `testboard`** — prefixed
   paths work out of the box, no flag needed on prod; `--url-prefix
   ""` disables; any other value works (configurable). Lands in
   `server.py`/`api.py`; `run_server.py` stays Python-2-parseable
   (argument plumbed without f-strings or annotations, same as its
   existing flags).
2. **Accept both shapes, always:** nginx passes the prefix through
   (confirmed — it will NOT strip), so `/testboard/api/summary` is
   handled as `/api/summary`; bare `/api/summary` keeps working
   everywhere (dev, staging, curl-on-the-box diagnostics), which is
   what makes the default-on flag zero-risk. Tests pin the
   pass-through shape specifically. Prefix stripping happens ONCE, at
   the top of routing, before path-traversal checks — and the
   traversal guard tests are re-run against prefixed paths
   (`/testboard/../etc/passwd` and friends must still 404/400), plus
   the non-path `/testboardX/...` shape must NOT match the prefix.
3. **Frontend audit, not rewrite:** the pages should already be
   prefix-agnostic IF every href/fetch is relative. The phase starts
   with a repo-wide audit of `static/` for root-absolute references
   (`href="/`, `fetch("/`, `src="/`, `location = "/`, redirects in
   `api.py`) — `static/urls.js` centralizing scoped URLs makes this
   tractable. Every hit becomes relative or prefix-aware. A guard test
   pins "no root-absolute URL in static/" so the bug family cannot
   return.
4. **The sanity net runs against a PREFIXED server** as part of this
   phase — the six-class walk under `--url-prefix` catches what a grep
   cannot (a link that renders relative but resolves outside the
   prefix). This is the phase's real acceptance test.
5. **Feeder: bypasses nginx entirely (decided — §0).** Feeders POST
   direct to the backend port, plain HTTP, no prefix — which the
   accept-both-shapes rule makes automatic. One test proves a feeder
   submit against a prefix-enabled server round-trips on the BARE
   path; the README's feeder section gains one line saying feeders
   use the direct port, not the nginx front door.
6. **Docs:** README + drop note document the flag (default-on means
   the drop note MUST name it even though prod needs no action — the
   flag-nobody-was-told-about rule). A SAMPLE nginx location block in

## 6. Phase 4 — the single-file feeders (WP-29)

**The problem, in the user's words:** more products are about to
onboard, and the current feeder runs off a link to a full checkout —
not maintainable. A contributing product should check ONE file into its
own repo; Copilot implementing each site's feeder stays the core
pattern, so the brief must give Copilot a template it can implement.

**The design (all decided — §0):** one distributable file per language,
site slot on top, engine below a do-not-edit line. What makes the
vendored copies maintainable is the frozen import contract — additive
only, old clients tolerated forever — not any distribution tooling.

**The invocation model (refined — §0), and what it changes:** the test
framework calls the feeder in its own CLEANUP phase, once per suite
execution, passing arguments — it is a short-lived push, not a poller.
Engine-defined arguments: `--environment` (required), `--build`
(optional — WP-25 collapsed stream kinds to `build` alone, so a
framework's "branch" parameter is passed AS the build value; the wire
has no `branch` and rejects one loudly), `--dry-run`, and whatever the
site slot declares for locating its own results (the template shows
`--results PATH` as the worked convention). Three consequences, each
now a design center rather than an inherited detail:

- **No high-water mark, no daily mode, no scanning window** — the
  framework knows exactly which execution just finished and hands it
  over. The deployed feeder's `state.py` machinery is NOT distilled
  into the single files. Idempotency comes from the server's upsert +
  fingerprint skip, so a re-invoked cleanup (frameworks retry) is
  harmless by construction.
- **Cleanup must never hang and never lie:** every HTTP call carries a
  timeout, total retry/backoff time is bounded and documented (target:
  worst case under ~2 minutes), and exit codes are a stated contract —
  **0** all valid records accepted; **1** server unreachable/refused,
  batch saved to a replay file (results are SAFE, submit deferred);
  **2** usage/validation error, nothing sent. The template tells the
  framework owner exactly which codes may fail their cleanup and which
  must not.
- **Replay files are the only persistence, drained opportunistically:**
  each invocation first re-submits any pending replay files (bounded,
  same timeout discipline), then its own batch; a failed batch becomes
  a new uniquely-named replay file (per-invocation names — concurrent
  cleanups from different environments on one host must not collide).
  Nothing else is written to disk.

**Deliverables:**

1. **`clients/feeder.py`** — single-file Python 3.6, distilled from
   the existing `feeder/` package (~120 KB across nine modules; a
   distillation, not a repackaging — and the poll/daily-mode and
   high-water-mark parts stay behind). Engine semantics: schema
   validation, batching at 500, retry ×3 with backoff (bounded as
   above), replay files per the invocation model, never abort on one
   bad record (log, skip, count), exit codes as above. Follows
   `run_feeder.py`'s rule: parses under Python 2 (no f-strings/inline
   annotations) so a wrong interpreter fails with a message, not a
   SyntaxError — and is therefore exempt from the inline-annotation
   requirement the same way `run_*.py` already are (the compat guard
   test learns the file).
2. **`clients/feeder.tcl`** — vanilla Tcl 8.5. `package require http`
   (bundled) for POSTs with `-timeout` on every call; JSON is
   hand-built on emit (flat records, escaping unit-tested) and
   hand-parsed on response via a small recursive-descent parser
   (~100 lines, unit-tested — needed for rejection counts and the
   `streams_seen` ack; never regex extraction). No `tls`, no tcllib,
   nothing beyond a bare tclsh 8.5. Same engine semantics, argument
   contract, exit codes, and site slot shape as the Python file.
3. **Both engines carry a version string + contract version** in the
   file header and send it as the **`User-Agent` header** on each
   import — NOT as a new JSON field (this drop made unknown wire
   fields loud rejections; a header touches nothing). The server can
   log it for fleet visibility, but no engine is ever REQUIRED to
   update — contract stability is the maintenance story.
4. **`--dry-run` in both engines**: validate records and print what
   would be sent, POST nothing — the acceptance gate a site can run
   on Copilot's reader with no network access to the dashboard.
5. **`docs/FEEDER_TEMPLATE.md`** — written FOR Copilot as the reader:
   the wire schema stated exactly, the invocation contract (how the
   framework's cleanup calls it, the argument set, which exit codes
   may fail cleanup), the one function to implement per language,
   worked examples (a log-scraping reader, a results-file reader —
   both shown as cleanup-invoked with `--results PATH`), the
   acceptance checklist (`--dry-run` clean against a real results
   capture, counts match a known sample), and what a site may NOT do
   (no extra dependencies, never edit below the line, never poll).
   Harvests the living parts of `FEEDER_BRIEF.md`; supersedes it.
6. **The conformance suite** (in `tests/`, this repo): drives each
   engine as a SUBPROCESS with a stub reader against a scratch
   dashboard server, same scenarios for both languages — bad record
   skipped and counted, retry then replay-file on persistent failure
   (exit 1, results in the file), a later invocation draining the
   replay file first, re-invoked cleanup is a no-op on the server
   (upsert + fingerprint; counts assert it), two concurrent
   invocations don't collide on replay names, the bounded-time
   promise (a black-holed server port must produce exit 1 within the
   documented ceiling, not a hang), `build:` + `streams_seen`
   handshake, old-server detection (absent `streams_seen` aborts a
   build-carrying feeder loudly, exit 1, replay saved). The Tcl
   variants are gated on a `tclsh` being present, same pattern as
   `TESTBOARD_TEST_DB_CNF` — absent, the variants do not exist.
7. **CI gains a Tcl leg** (approved — §0): tclsh in the image, the
   conformance suite's Tcl variants run on every push.
8. **Transport note in both the template and README:** feeders use
   the backend port directly, plain HTTP — never the nginx front
   door, never the prefix. (Phase 3 tests pin that bare paths keep
   working precisely so this stays true.)

**NOT in this phase:** migrating the deployed feeder (decided — it
runs untouched off its checkout, first migration candidate later);
any board-visible change; any change to the import contract's
