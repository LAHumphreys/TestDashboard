## What changed, fixes first

**Fix — a build's "Its own results" tab is always reachable.** Opening a
branch build (`index.html?stream=<id>`, via the Build picker or a Watch
card) showed ONLY the "Difference from mainline" view unless the build had
completed two covered passes in the last 14 days. A fresh branch build —
the case that came up the first day branch builds were loaded — listed
what differed and nothing else, and nothing on the page said how much of
it had actually run. The own-results view (the home dashboard scoped to
the build: tiles, trend, triage queues, browse table) already existed from
WP-23; WP-25 had gated its *existence* on the same threshold that WP-23
used only to pick the *default*. This drop restores WP-23's shape:

- both tabs are shown on every stream-scoped load;
- the covered-pass threshold picks which opens first, nothing else;
- the caption under the tabs says which tab opened and why, from the
  build's own covered-pass count and the threshold, in every case — the
  below-threshold wording now also says what the other tab shows;
- a URL carrying browse-filter params (`result=`, `unassigned=1`,
  `stale=1` — what a Watch card's "N unassigned failures" link builds)
  opens on "Its own results" whatever the cadence, because only that
  tab's browse table reads them. Before, on a sparse build, that link
  landed on the comparison and the filter was silently dropped.

Files: `static/app.js` (`initBranchDashboard`, new
`urlAsksForBrowseFilters`), `static/index.html` (a comment),
`static/whatsnew.html`, `tests/test_frontend_calls.py`
(`OwnResultsAlwaysReachableTest`, +5, proven to fail against the previous
`app.js`).

**Not changed, deliberately:** the Watch page's build card (the user judged
it fine as it is), every API endpoint, and the 36-hour fallback clamp on a
sparse stream's own `stale_before` (CLAUDE.md forbids loosening it; see
"What was NOT verified" for what that means on screen).

## Deploy

Same order as every static-only drop. On the box:

```
sudo systemctl stop testboard        # or however the service is stopped there
cd /opt/testboard && git fetch && git checkout <this drop's commit>
sudo systemctl start testboard
```

**Restart the server — not optional.** Static files are read from disk per
request, so a stale process would serve the new `app.js` fine, and this
drop would appear to work without a restart. It is still the standing rule
(CLAUDE.md), because the next drop that DOES change a handler will be
deployed by someone who remembers "last time we didn't need to".

No database step. No feeder step. Staging (SQLite) and production
(MariaDB) take the identical procedure.

## Check it came up

1. `What's new` in the nav shows **23 September 2026**.
2. Open any product's Build picker and choose a build that has run
   **once**. Two tabs appear above the page: "Its own results" and
   "Difference from mainline". The page opens on the difference, and the
   line under the tabs reads "Showing the difference from mainline first —
   this build has completed N pass(es) in the last 14 days (2 or more opens
   its own results first). “Its own results” shows everything that has run
   on this build, whether or not it differs."
3. Click "Its own results": the tiles read "N tests tracked" with the
   build's own count, and the browse table lists every test that has a
   result on the build.
4. Open the Watch page, click a build card's unassigned-failures number:
   the dashboard opens on "Its own results" with "Unassigned only"
   pressed and the caption starting "Showing its own results, filtered as
   the link asked".
5. A plain `index.html` (no `stream=`) is unchanged: no tabs, no band.

## What was NOT verified

- **No real browser has rendered this**, as with every drop here. The
  live evidence is the scratch DOM-shim driver
  (`.scratch/net/wp31_drive_branch_tabs.mjs`, not in the repo) against a
  server booted from this commit on a seeded copy of the dev estate:
  a one-run build shows both tabs, opens on the difference with the
  stated caption, reaches its own results in one click (tiles render with
  its own count of 3, Time/Timeline quick links appear), a
  `result=FAIL&unassigned=1` URL opens on its own results with the toggle
  pressed, and a mainline load is byte-for-byte unchanged (band, tabs,
  caption, delta all stay hidden). The at-or-above-threshold path was
  exercised on a re-seed with the nights shifted into the last fortnight:
  a build with 5 covered passes opens on its own results (4,449 runs on
  its tiles), and every check above passes on that seed too.
- **A build whose last run is more than 36 hours old shows "Reported 0 of
  N" and "nothing has reported since …" on its own tiles** until it runs
  again. That is the unchanged 36-hour fallback for a stream with no
  covered pass, worded from the real window as always; the "N tests
  tracked" line and the browse table still show everything that ran. It
  is the honest reading of an old one-shot build, but a tester may report
  it. Not changed in this drop because the clamp is load-bearing
  (CLAUDE.md) and a build-specific window is a design decision, not a
  fix.
- Production scale: nothing here adds a query. `/api/summary?stream=` and
  `/api/compare` are the same two requests a stream-scoped load already
  made; the tab click re-uses `refreshAll()`, unchanged.
