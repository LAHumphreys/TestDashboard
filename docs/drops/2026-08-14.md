## What changed, fixes first

**Fixes:** none. This is a pure feature drop — the first of four
(`docs/STREAMS_PLAN.md`), products before streams, because it is the
cheapest slice with no import-contract change.

**The feature**

1. **Products.** An environment can now be declared as belonging to a
   product (`PUT /api/environments/{env}/product`, mirroring the existing
   expectation endpoint — a Product cell sits next to it in Open actions'
   "Environment expectations" section). `product=` is now accepted by
   `/api/dashboard`, `/api/summary`, `/api/time` and `/api/timeline`,
   resolved server-side to the product's environments. **A deployment with
   fewer than two declared products sees ZERO visible change** — no
   switcher, no new column, no new words anywhere. This was the explicit
   design constraint and it is what most of the testing below is checking.

2. **The header product switcher** (`static/products.js`) appears once a
   second product is declared, on the Dashboard, Open actions, Time,
   Timeline and Watch pages only — not What's-new/Script/Test, which show
   no scoped data. Selection persists per browser (localStorage); changing
   it reloads the page. Dashboard and Open actions already fetch
   `/api/summary` for their own headline data, so on those two pages the
   switcher's mount point is marked `data-host-managed` and the page
   renders it from data it already has, rather than the switcher fetching
   `/api/summary` a second time — those are the two heaviest-traffic pages
   in the app. Time, Timeline and Watch fetch no summary of their own and
   keep the switcher's independent fetch.

3. **The Product column** on the Dashboard's "All tests" table and Open
   actions' table, shown exactly when the page spans products; scoped to
   one, the footer says "Scoped to `<product>` — no product column
   needed." instead of showing a column of identical values.

4. **A new page: Watch** (`static/watch.html`), in the nav of every page.
   One page, a grid of cards — each an environment or (once declared) a
   product — showing failing / new failures / fixed and its own
   freshness, dated from its own data. **The URL is the entire
   configuration**: `watch.html?c=e:lab-alpha&c=p:Atlas`, no account, no
   server-side saved view. "Save as my default" and a visible read-only
   "Copy link" field are the only two persistence affordances (both
   localStorage-backed, same mechanism as the What's-new unread dot).
   Cards are editable in place — add, remove, up/down reorder. A card for
   a name that no longer exists renders as a plain error card ("nothing
   under this name — removed or renamed?"), not a silent gap; a request
   naming more than 50 cards is refused (413) with the limit stated.
   `GET /api/watch` answers the whole page from ONE fetch of each derived
   table regardless of card count — pinned by a test that asserts the SQL
   query count is identical for 1 card and 50.

5. **New endpoint:** `GET /api/watch`. Existing endpoints gained fields
   (`"product"` on dashboard/queue rows and on `/api/environments` items;
   `"products"` on `/api/summary`) — additive, nothing existing changed
   shape. `/api/import` is untouched; product is not on the wire.

**Performance:** not separately measured this drop. Every new filter
(`product=`) reuses the existing `environment IN (...)` machinery the
environment filter already exercises — same cost shape, no new query
pattern — and the one genuinely new endpoint (`/api/watch`) is bounded by
the derived tables the way every other estate-wide read is. No endpoint
existing before this drop changed its query shape.

## Upgrade procedure

Same drill as the last two drops: **a migration runs, so the database copy
is the rollback.**

```bash
# 1. On your machine: confirm what you are shipping.
git log --oneline origin/master..wp-20-products
python -m unittest discover          # expect 1491 OK (skipped=1)

# 2. Push (after acceptance).
git push origin wp-20-products:master

# 3. On the server, with the feeder NOT importing:
cd /path/to/testboard
sudo systemctl stop testboard

cp testboard.db      testboard.db.pre-2026-08-14          # THE rollback
cp testboard.db-wal  testboard.db-wal.pre-2026-08-14      # if present
cp testboard.db-shm  testboard.db-shm.pre-2026-08-14      # if present

git pull
sudo systemctl start testboard       # first start runs migration 8 — see above
```

**The restart is not optional**, as ever: a stale process serves this drop's
`watch.html`/`products.js` against handlers that have never heard of
`/api/watch` or `product=`, and the page fails in a way that looks exactly
like a UI bug rather than a deployment step skipped.

### Check it came up

```bash
curl -s "localhost:8000/api/summary?parts=headline" | head -c 200   # 200, JSON, has "products"
curl -s "localhost:8000/api/watch" | head -c 100                    # 200, {"cards": [], "cap": 50}
curl -s -o /dev/null -w '%{http_code}\n' localhost:8000/watch.html  # 200
```

In a browser, hard-refresh (Ctrl-Shift-R) and check:

- Every page still looks exactly as it did before this drop — no switcher,
  no Product column, no new nav entry EXCEPT "Watch" (which is deliberately
  never hidden, per spec, since environment cards work with zero products
  declared).
- Open the Watch page bare: it shows the "add a card" how-to, not a blank
  page or an error.
- Add an environment card, confirm its numbers and its freshness line, and
  that "Open in dashboard →" lands on that environment. Add a second
  environment card, reorder with the arrows, remove one, confirm "Copy
  link" holds the URL that reproduces the current set exactly.
- Declare a product for two environments (Open actions → Environment
  expectations → Product cell), reload any page: the switcher appears,
  the Dashboard and Open actions tables gain a Product column when "All
  products" is selected and lose it (with the footer line) when scoped.
- Clear both declarations again: the switcher and column disappear;
  confirm the rest of the page is unaffected.

### Rolling back

```bash
sudo systemctl stop testboard
git checkout <previous-commit>
cp testboard.db.pre-2026-08-14 testboard.db           # REQUIRED, not optional:
cp testboard.db-wal.pre-2026-08-14 testboard.db-wal   # v7 code REFUSES a v8 file
sudo systemctl start testboard
```

Anything imported between upgrade and rollback is in the file you just put
aside, not the one you restored — re-run the feeder for the gap (safe: the
server upserts).

  That proves the API; it proves nothing about layout, the switcher's

  Product column reads cleanly at a real screen width.
- **The dual-backend (MariaDB) test variants have now run, against the
  dev machine's local `mariadbd` (port 3307, `.scratch/mariadb-test.cnf`,
  a sacrificial database) — 1919 green (skipped 13).** This includes the
  generated `TestEnvironmentProductMariaDB`, `TestEnvironmentProductsMariaDB`,
  `TestEnvironmentsForProductMariaDB` and `TestWatchMariaDB` classes, all
  passing against the real `environment_products` DDL (`SHOW CREATE TABLE`
  confirmed a `varchar(64)` PK on `environment`, matching the exporter).
  One test needed a new exclusion entry:
  `TestWatch.test_query_count_does_not_grow_with_card_count` uses

  SQLite-specific instrument several existing tests are already excluded
  for — added to `EXCLUDED_TESTS` in `tests/test_mariadb_backend.py`

  this is the dev machine's local MariaDB, not CI's `mariadb:10.3` service

  has not been observed, only the local equivalent.
- **Production numbers are projections.** The only timing in this note (the
  migration) is from the 220 MB dev copy; production is roughly 4x that on
  a network mount and has not been measured from here — though migration
